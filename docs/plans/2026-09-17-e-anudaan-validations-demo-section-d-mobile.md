# e-Anudaan — document validations, sample files, one-click demo fill, §D, and the phone column

**Asked 17 Sep 2026:** build every kind of document validation the clone cycles and the reference
screenshots showed; build sample files that pass and fail each one; put one-click fills for every
form on the demo rail, with the right data and with data that trips each validation; complete the
five items of the meeting plan's §D to best practice; complete the phone screens.

Five phases, each its own branch and PR, each merged when done.

---

## Phase 1 — Every document validation, as one catalogue

**Evidence.** 328 live captures (`tools/design-audit/projects/e-anudaan/captures/live/*.json`) hold
177 distinct validation-like messages. Grouped by what the live checker was judging, they are the
checks below. Where live gives a verdict, we keep its severity; where live is silent and best
practice needs a check (a password-protected PDF, a file whose bytes are not what its name says),
the check is ours and is marked so.

| Check | Stage | Outcome | Live evidence |
|---|---|---|---|
| Wrong file type | before upload | refused | "PDF / JPG / PNG · Max 5 MB per file" · "PDF · Max 5 MB" (AVYAY) |
| Over the size limit | before upload | refused | same line |
| Empty file (0 KB) | before upload | refused | ours |
| Password-protected PDF | before upload | refused | ours — a checker cannot read it, an officer cannot open it |
| File is not what its name says | before upload | refused | ours — a `.pdf` whose bytes are an image or nothing |
| Upload interrupted | upload | failed | "Upload failed. RETRY" |
| Placeholder or test file | check | not valid | "✗ Document not valid — Test/placeholder document" (×100+) |
| Wrong document for the slot | check | not valid | "Wrong document: PAN card uploaded instead of Annual Report" |
| Wrong financial year | check | not valid | "Document is an annual report for 2024-25, but 2025-26 is required." |
| Wrong variant of the right document | check | not valid | "this is an audited UC for 2024-25, but a provisional UC for current…" · "please upload the GFR 12-A format" |
| Mandatory particulars missing | check | not valid | "The registration number is not present." · "must include a Chartered Accountant's declaration, signature" |
| Required parts missing | check | not valid | "must contain the balance sheet, income & expenditure statement, and auditor's report" |
| Another organisation's document | check | not valid | ours, built on "Organisation Name" extraction |
| Blank or unfilled template | check | check the details | "⚠ Needs review — Rent Agreement Template (blank/unfilled)" |
| Validity does not cover the year | check | check the details | "Agreement must show commencement and expiry dates covering the current financial year" |
| Not notarised / no seal | check | check the details | "No notarisation seal or certificate visible." |
| Table incomplete | check | check the details | "Staff list must include category, honorarium/salary, and period of employment" |
| Address differs from the application | check | check the details | "Full project address must … match the grant application" |
| Bank details differ from the application | check | check the details | IFSC / account compared; "The account number appears to be 13 digits … please verify" |
| Account not in the organisation's name | check | not valid | "The account must be in the name of the NGO/VO" |
| Illegible or low-resolution scan | check | check the details | "OCR quality is poor … confidence is 82% (needs 90%)" |
| Automatic check unavailable | check | saved for a hand check | "Automatic check unavailable — … a reviewer will verify it by hand" |

**Build.** `lib/e-anudaan/doc-checks.ts`: the catalogue — id, stage, outcome, the documents it
applies to, applicant words, officer words, the live evidence. `simulateCheck` consults it. Byte
checks (empty, encrypted, not-what-it-says) run on the real file in the browser.

## Phase 2 — Sample files that pass and fail

Real files under `apps/hub/public/portals/e-anudaan/demo-documents/`, generated by
`tools/e-anudaan-samples/` so they can be regenerated, never hand-edited. One passing file per
document type, and a failing file for every check that applies to it. Each file LOOKS like its
defect when opened — the rent agreement with an expiry in 2025 carries that date; the placeholder
carries "SPECIMEN — NOT A REAL DOCUMENT". The file name carries the check id, so the prototype's
checker recognises it; a manifest lists every file, its document type and the verdict it produces.

Files over 5 MB are not committed: the demo rail builds them in the browser.

## Phase 3 — One-click fills on the demo rail, for every form

For each form: **Valid** (the right data, passes every rule) and one preset per rule it enforces
(the data that trips exactly that rule). Forms:

- the grant wizard, every scheme and branch (SHRESHTA Mode 2, AVYAY, NAPDDR, SMILE × new and
  instalment) — including a **Documents** panel: every sample for the open checklist, placed into
  its slot in one click, and "Every check at once", which fills each slot with a different failure;
- Project Location Change · Bank account change · Add beneficiary · Add staff · Weekly attendance ·
  CCTV setup · Correct your application (deficiency response) · Utilisation Certificate;
- officer: remarks (forward / query / return) · show cause · schedule and record inspection ·
  the Director's sanction, return and reject.

## Phase 4 — §D, completed

1. **Sign in with NGO-DARPAN** replacing the captcha login — redirect-based identity-provider flow
   with consent, every return state designed (linked, first link, not registered, inactive
   registration, consent refused, provider unavailable), no captcha (WCAG 2.2 SC 3.3.8).
2. **CCTV module** — register cameras against mandated coverage areas, privacy exclusions,
   installation certificate, retention, monthly uptime declaration; officer compliance view.
3. **Officer read-only roster and attendance** — beside the NGO 360 and the review, identifiers
   masked, read-only by construction.
4. **Which fields an ongoing application may edit** — one policy, per field: locked (with the
   reason and where to change it), editable, or editable with a stated reason.
5. **Error catalogue** — every failure an API can return, with its words, its action and where it
   shows; wired to real screens and triggerable from the demo rail.

## Phase 5 — The phone column, complete

The library masters that cannot yet go narrow are given narrow arrangements; every remaining phone
frame is drawn and measured against the portal at 375; the build itself is audited at 375 against
UX4G's mobile recommendations (44px touch targets, input types, sticky actions) and fixed where it
falls short.
