# DoSJE Live-Data Ingestion — Design Spec

**Date:** 2026-06-13
**App:** `apps/dosje/` (the unified DoSJE website)
**Status:** Approved design → ready for implementation plan

## Problem

`apps/dosje/` is a faithful **design and structure** clone of dosje.gov.in, but it is **not** a data copy. Its data-driven collections exist only as small hand-coded samples inside `[slug]/page.tsx` files. Verified gap (live vs local), measured 2026-06-13 from the live WordPress sitemaps:

| Collection | Live | Local | Coverage |
|---|---|---|---|
| Schemes & Services | 141 | 4 | ~3% |
| Events | 102 | 6–7 | ~6% |
| Documents | ~1,076+ | ~9 sample rows | <1% |
| Officials / Who's-Who | 550 | ~3 | <1% |
| Gallery | 488 | 1 | <1% |
| Tenders | 400 | ~3 | <1% |
| Vacancies | 155 | ~3 | ~2% |
| Associated Organisations | 16 | 8 | 50% |
| Static informational pages | 86 | ~70 | ~80% |

**Goal:** ingest the real content so the clone contains all *unique* pages and records from the live site, with a repeatable way to verify completeness.

## Decisions (locked)

1. **Ingestion = one-time scrape → committed JSON.** Fits the current static Next.js architecture (no backend; `generateStaticParams` already in use). Build stays independent of live-site uptime; data is git-diffable; re-running refreshes. (Headless CMS deferred as a future, separate project. Build-time live fetch rejected as too fragile for a government site.)
2. **Scope = phased, high-value first** (see Phasing).
3. **Assets = Hybrid.** Download images into the app; keep large PDF documents pointing at their live CloudFront/dosje URLs (recorded in the manifest for a later self-host pass).
4. **Image weight = gitignore + regenerate.** Downloaded binary assets are gitignored and regenerated by the ingestion script at build time. Committed data is text JSON only. (Reversible: flip to commit-images if a deploy target needs fully self-contained assets.)
5. **Dedup rule = skip redundant, copy all unique.** Canonicalize and drop WordPress duplicates; never drop a unique page. (See Deduplication.)

## Data source

dosje.gov.in is WordPress, so the primary source is its **REST API** (`/wp-json/wp/v2/<type>`) for custom post types: `schemes-and-services`, `organisation`, `events`, `documents`, `official`, `tender`, `vacancies`, `gallery`, plus taxonomies. This returns structured JSON with all fields — far cleaner than HTML scraping.

- **Fallback:** if a post type is not REST-exposed (`show_in_rest=false`), that collection falls back to per-URL HTML extraction driven by its sitemap.
- **Verification source of truth:** the WordPress sitemaps (`wp-sitemap-posts-<type>-N.xml`) provide the canonical URL universe and per-collection counts.

## Architecture

### Pipeline — new `scripts/ingest/`

```
scripts/ingest/
  fetch.mjs       # paginated WP REST pull (retry + rate-limit); sitemap/HTML fallback per collection
  transform.mjs   # raw WP record → typed schema; cleans fields, strips WP markup cruft
  dedup.mjs       # canonicalize URLs, drop redundant duplicates, log skipped (see Deduplication)
  assets.mjs      # HYBRID: download images → public/content/<col>/; rewrite img refs; keep PDF links live
  verify.mjs      # compare sitemap counts vs ingested counts → sync report
  index.mjs       # orchestrator: runs the above, writes src/content/<col>.json + manifest.json
```

- **Idempotent:** re-run overwrites output cleanly; safe to run repeatedly.
- **Resilient:** retry with backoff and polite rate-limiting on all network calls; a single failed record is logged and skipped, not fatal (surfaced in the report).
- **Configurable scope:** `node scripts/ingest --only=schemes,organisation` runs a subset; default runs all enabled collections.

### Output & types

- `src/content/<collection>.json` — committed structured data (one file per collection).
- `src/content/manifest.json` — per-collection counts, source-URL list, skipped-duplicate log, and an ISO timestamp. Committed.
- `src/types/content.ts` — typed interfaces for every collection record.
- **Zod schemas** validate every record at ingest and at build; a malformed record fails the build.
- `src/lib/content/` — small typed loaders (`getSchemes()`, `getScheme(slug)`, `getOrganisations()`, …). Pages import only from here, never from raw JSON.

### Page wiring

- Dynamic routes (`schemes-services/[slug]`, `organisation/[slug]`, `events/[slug]`) **drop their inline objects** and read via loaders; `generateStaticParams` enumerates **every** ingested slug.
- Existing listing pages render the full ingested arrays instead of hand-coded rows.
- New collections (documents, officials, tenders, vacancies, gallery) get listing routes built on the existing `ListingPage` template, plus detail routes where the live site has them.
- Homepage `LatestUpdates` and `RecentDocuments` components are fed from the real documents/updates data.

### Deduplication (skip redundant, copy all unique)

`dedup.mjs` canonicalizes before writing and removes only true duplicates:
- **`home-page/` prefix duplicates** — live serves some pages at both `/x/` and `/home-page/x/` (e.g. terms-conditions, privacy-policy, sitemap). Keep the canonical top-level slug; skip the prefixed twin.
- **WordPress `-copy` and `-N` siblings** — e.g. `…-emerging-cyber-threats-copy`, `minutes-of-screening-committees-2`. Keep the original; skip the auto-duplicate **only when content is substantively identical** (normalized-text hash match). If the `-2` variant has different content, it is a unique page and is kept.
- **Cross-collection echoes** — a scheme that also appears as a document/organisation is stored once per its canonical collection and cross-referenced, not duplicated.
- Every skip is recorded in `manifest.json` with the reason, so "skipped" is auditable and never silent.

### Assets — Hybrid

- **Images** → downloaded to `public/content/<collection>/`, references rewritten to local paths. Directory is **gitignored**; `assets.mjs` runs as part of the build to regenerate.
- **PDFs / large documents** → references kept as live CloudFront/dosje URLs, with the canonical URL stored in the manifest so a future "self-host all documents" pass is a config flag, not a rewrite.

## Phasing

- **Phase 0 — Infrastructure.** Build the pipeline, content types, Zod schemas, and loaders. Prove end-to-end on **Organisations (16)**: REST pull → transform → dedup → assets → JSON → loader → page render → verify report green.
- **Phase 1 — Citizen core.** **Schemes (141)** + **Officials/Who's-Who (550)**, wired into listing + detail pages.
- **Phase 2 — Long tail.** **Documents (~1,076)**, **Events (102)**, **Tenders (400)**, **Vacancies (155)**, **Gallery (488)**.
- **Phase 3 — Completeness.** Add the ~12 missing **unique static pages** (e.g. `list-of-scheduled-castes`, `handbook-on-social-welfare-statistics`, `supreme-court-judgement`, `lok-sabha-question-answer`, `newsletter`, `cpio`, `detailed-demand-for-grant`, `grants-suspended-list-blacklisted-ngos`, `list-of-de-blacklisted-ngos`, `special-mention-matters-raised-under-377`, `minutes-of-screening-committees`), and feed homepage `LatestUpdates`/`RecentDocuments` from real data.

## Verification & testing

- **Build gate:** Zod validates every record; build fails on malformed data.
- **Sync report:** `verify.mjs` asserts ingested count ≈ live sitemap count per collection (accounting for deduped redundancies), and emits a human-readable report. This is the repeatable answer to "is the website synced?".
- **Golden records:** snapshot tests on a few representative records per collection guard transform regressions.
- **Route check:** every ingested slug resolves (no 404) via `generateStaticParams`; spot-checked against the live sitemap URL set.

## Trade-offs & risks

- PDF hotlinks mean documents depend on dosje.gov.in staying online (accepted per Hybrid; reversible via the manifest).
- WP REST may not expose every custom post type; the HTML-fallback path covers that but is slower and more brittle per-collection — flagged for Phase-by-phase validation.
- Gitignored images mean a fresh checkout must run the ingestion/asset step before images appear locally (build does this automatically).

## Out of scope

- Headless CMS / editorial workflow (future project).
- Self-hosting the full PDF corpus (deferred; manifest makes it a later flag).
- Visual/design changes — this work is data only; pages keep their current templates and styling.
- Translations / Hindi content parity (tracked separately).
