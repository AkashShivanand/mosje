# 11 — Set up Figma Code Connect (design ↔ code, kept in sync automatically)

> **Read `00-MASTER-documentation-law.md` in full before anything else.** Its hard rules, tooling
> table and pressure-test discipline all apply. Its four-phase spine does **not** — this is not a
> foundation, and its phases are different. They are stated below.
>
> **Run this last.** Code Connect maps *components*; it is worth wiring once the foundations those
> components are built from are settled.

---

## WHAT THIS IS, AND WHAT IT IS NOT

Code Connect makes a Figma component show **your real code** in Dev Mode — the actual import, the
actual props, the actual snippet — instead of Figma's autogenerated CSS guess. It is the mechanism
that stops a developer reading a design and inventing a component that already exists.

**It is not:** a token sync (that is `@mosje/tokens` → `figma.variables.json`, already built and
working), a design-to-code generator, or a way to push code into Figma's canvas.

**Be precise about "automatically" in everything you write and report.** Code Connect does not
detect drift by itself. It publishes a mapping, and the mapping goes stale silently when either side
changes. **The automation is the CI job and the parity test you are going to build** — that is the
deliverable that makes the sync real rather than ceremonial. Say so plainly rather than implying
Figma does it for you.

## PHASE B — THE 98 ICONS ARE ONE MAPPING, NOT 98

Do not author 98 Code Connect files. `<Icon>` takes a `name` prop and renders a Material Symbols
ligature; the correct mapping is **one** entry that resolves any icon component to
`<Icon name="…" />`, with the glyph name taken from the Figma component's name.

This is exactly why `08-iconography.md` requires the Figma component names to match the Material
Symbols ligatures exactly. **If that prompt has not run yet, verify the name match yourself here** —
a mapping built on mismatched names produces 98 broken snippets.

## PHASE C — WIRE IT

### Layout

- `figma.config.json` at `packages/design-system/` root — parser `react`, include globs, and the
  `documentUrlSubstitutions` for the file key so URLs are not repeated in every file.
- **Colocate** each mapping next to its component: `components/actions/button.figma.tsx` beside
  `components/actions/button.tsx`. A mapping in a distant folder rots because nobody editing the
  component sees it.
- Add `@figma/code-connect` as a **devDependency** of `packages/design-system` only. It must not
  reach an app bundle.

### Per component

1. `get_context_for_code_connect(fileKey, <componentSetNodeId>)` → the real property and variant
   names. **Never guess a variant name**; Figma's are case- and space-sensitive.
2. `get_code_connect_suggestions(...)` → review, do not accept blindly. Suggestions are a draft.
3. Author the `*.figma.tsx`, mapping Figma props → React props with `figma.enum`, `figma.boolean`,
   `figma.string`, `figma.children`, `figma.instance`.
4. The `example` must be **the code a developer should actually write** — the real import path
   (`@mosje/design-system`), real prop names, real children. A snippet that would not compile is
   worse than no snippet.
5. Publish, then **open Dev Mode on that component and confirm the snippet renders**. Publishing is
   not the same as having published successfully.

### Order

Map in dependency order, starting with the atoms every other component composes: Button, Badge,
Chip, Checkbox, Radio, Toggle, Input, Select, Search, Avatar, Alert, Loader, Card, Tooltip,
Empty State. Then composites. `list_file_components_for_code_connect` returns the dependency graph —
use it rather than guessing.

**Do not map all 84 in one pass.** Map the atoms, publish, verify in Dev Mode, and report before
continuing. A mapping error repeated 84 times is 84 wrong snippets in front of every developer.

## PHASE D — MAKE IT STAY IN SYNC (the part that matters)

Without this, the mappings are a snapshot that silently rots. Build all three:

1. **A parity test** in `packages/design-system/__tests__/` that fails when a mapping references a
   React prop that no longer exists, or a Figma variant that no longer exists. Run it in CI. This is
   the drift detector; nothing else in the pipeline catches a renamed prop.
2. **A CI publish job** — on merge to `main`, when `packages/design-system/**` changes, run
   `figma connect publish`. Needs a `FIGMA_ACCESS_TOKEN` **repository secret**. State plainly that
   the token is a secret, that it must never be committed, and that this session neither reads nor
   sets it — **the user creates it themselves.**
3. **A `figma connect publish --dry-run`** on pull requests, so a mapping that would fail to publish
   fails the PR instead of `main`.

Add `npm run figma:connect` and `npm run figma:connect:check` scripts so a human can run both
locally.

**Verify the CI job actually works** — a workflow file that has never run is not a working
automation. If it cannot be verified in this session (missing secret), say so explicitly and list
what the user must do.

## HARD RULES SPECIFIC TO THIS WORK

- **Never commit a Figma access token.** Not in `figma.config.json`, not in a workflow file, not in
  a comment. Repository secret only. If you need one to test, stop and ask the user to create it —
  **do not ask them to paste it into the chat.**
- **Do not modify the Figma library's components** to make a mapping easier. If a component set's
  variants are wrong for code, that is a **finding to report**, not a thing to fix silently in a
  published library other files depend on.
- **Do not rename React props** to match Figma. The code is the source of truth for code. Map, don't
  conform.
- **`dbim` never reaches Figma** (see the master).
- Work on a branch; no AI co-author trailers.

## PRESSURE TEST

1. **The developer in Dev Mode.** Open five mapped components cold. Is the snippet copy-pasteable
   into a portal page and does it compile? Actually try it.
2. **The designer.** Does every mapped component show the right code, and does every *unmapped* one
   have a stated reason a designer can find?
3. **The adversarial reviewer.** Rename a React prop locally and confirm the parity test fails.
   Rename it back. **If the test does not fail, it is not a test.**
4. **The security reviewer.** Is any token, key or file id committed that should not be? Is the CI
   job scoped to the minimum permission?
5. **The peer design-system manager.** What happens when a Figma component is renamed? Deleted?
   Moved to another page? Does the mapping break loudly or silently? Document the answer.

**Score 1–5** on: ledger completeness · mapping correctness · snippet quality · drift resistance ·
documentation clarity. Anything below 4 gets fixed, not explained.
